1 · The task, grounded in the game

rotten.db keeps world = {[x y] tile} — a dense 30×30 maze grid (generate-maze fills every cell). The render loop is point-dominated: each frame, FOV (radius 10, ~314 cells) reads each visible tile ~3 times (get-tile, get world, get-tile-entities), then display-seen reduces the whole world once. A* pathfinding adds more point reads between frames.

4 · Sensitivity — the verdict depends on the frame mix

sensitivity.depends_on_weights = true: the candidate wins on scans and loses on points. Other :weights can reverse the verdict. The smallest flips:

The 900:1 weights model one rendered frame of this game. A workload with ~6× more full-world scans per point read (e.g. many entities re-planning routes over a smaller FOV), or a memory-priced objective, would favor csf. The task was not changed to make a candidate win.

5 · Outcome

no-change Descent keeps the starting plan — one order [0 1] :hash, the layout equivalent of the persistent nested map the game already uses. No neighbor is better, so nothing is accepted (accept requires a measured better verdict). The gate passed (293 checks, 0 mismatches, no warnings) and the emitted namespace is available as a preview.

For this dense, point-dominated render loop, the naive map is not naive: it is the measured optimum of the single-decision search space. The interesting result is the trade-off csf offers — 2× scans, 45% less memory — and exactly how far the frame mix must shift before it wins.
